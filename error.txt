When converting PowerShell cmdlets to PSADT functions, persist explicitly defined common parameters such as ErrorAction. 

Conversions of PowerShell cmdlets to PSADT functions do not preserve parameters that would change the behavior of the PSADT function. For example, Remove-Item -Path "C:\Program Files\IT Client Utility" -Recurse -Force -ErrorAction SilentlyContinue gets converted to the Remove-ADTFile function but without the -Recurse parameter (-Force is not a supported parameter). 

For v3.x to 4.x conversion, code that is captured as a raw PowerShell block will contain old PSADT 3.x variables e.g. $dirFiles instead of $($adtSession.DirFiles). If not too complicated, find and replace any 3.x variables with their 4.x equivalents before constructing the raw code block.
