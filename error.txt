Start-Process is converted into a Run Process card (which generates Start-ADTProcess).
Copy-Item is converted into a Copy File card (which generates Copy-ADTFile).
Remove-Item is converted into a Remove File/Folder card (which generates Remove-ADTFile or Remove-ADTFolder).
New-ItemProperty / Set-ItemProperty are converted into a Set Registry Key card (which generates Set-ADTRegistryKey).

The parser only specifically hunts for native PowerShell commands that represent very common "installation steps" that map cleanly into our visual UI cards (like copying files, removing files, setting registry keys, or launching an executable).

For everything else—such as Invoke-Command, Get-Service, Start-Service, Set-Content, Add-AppxPackage, loops, conditionals, etc.—the parser will not convert them.

Instead, it safely wraps those unrecognized commands into a "Raw PowerShell" card. This means they are emitted directly into the final script exactly as you wrote them, ensuring your complex logic remains 100% intact.

(The only thing that happens to them inside a Raw PowerShell card is that any legacy variables like $dirFiles are modernized to $($adtSession.DirFiles) so they work correctly in the v4 context).
