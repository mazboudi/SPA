When converting 3.x function Remove-MSIApplications to 4.x  Uninstall-ADTApplication, we are not specifying -NameMatch (‘Contains’, ‘Exact’, ‘Wildcard’, ‘Regex’). The Uninstall Application builder card defaults the Name Match dropdown to Exact even though ‘Contains’ is the default if -NameMatch is not specified. -NameMatch is only specified in the command preview if you select an option other than Exact. Additionally, there are invalid options of ‘StartsWith’ and ‘EndsWith’. Example from Desktop Messaging Client script conversion /Users/wissammazboudi/Development/SPA/RefactorApps/samplePSADT/Verient-DEsktop-Deploy-Application.ps1

Original command: Remove-MSIApplications -Name 'Desktop & Process Analytics Client*' -WildCard -Parameters '/qn /norestart' 

Converted command: UninstallADTApplication -Name ‘Desktop & Process Analytics  Client*’ -ApplicationType ‘MSI’ 

Correct converted command should be: UninstallADTApplication -Name ‘Desktop & Process Analytics  Client*’ -NameMatch ‘WildCard’ -ApplicationType ‘MSI’ 

The screenshot indicates we are always defaulting the -NameMatch dropdown selection to Exact (default should be ‘Contains’) instead of matching the original command’s intent.  

Related to the Uninstall-ADTApplication issue described above, conversion of 3.x function Get-InstalledApplication to 4.x function Get-ADTApplication specifies the type of name match to do without using the -NameMatch parameter. Unlike the 3.x function which lets you specify the type of match by specifying -Exact, -WildCard, etc, the 4.x function requires we use the parameter -NameMatch (e.g. -NameMatch ‘Exact’ or -NameMatch ‘WildCard’).
