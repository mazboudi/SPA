Start-Process is NOT being converted to Start-ADTProcess by the parser. Confirmed by direct test — the Zscaler uninstall containing $env:ZSCALER_PASSWORD + Start-Process produces a single raw_ps block with both lines preserved verbatim. The most likely explanation for Joe's observation is that the compat checker warnings (which showed "Use Start-ADTProcess instead") looked like conversion instructions in the UI.

Fixes Applied


parsePsadt.js
 — ADT_CMDLET_RE cleanup:

Removed Copy-Item, Remove-Item, Start-Process, Stop-Process from the regex
Added an explicit code comment documenting which native PS cmdlets must never be converted
Start-Sleep kept (it's a pure timing function, not semantically different from the PSADT context)


psadtCompatCheck.js
 — Compat checker warnings removed for:

Start-Process -FilePath → was: "Use Start-ADTProcess instead"
Copy-Item -Path → was: "Consider using Copy-ADTFile"
Remove-Item -Path → was: "Consider using Remove-ADTFile"
New-Item -ItemType Directory → was: "Consider using New-ADTFolder"
Set-ItemProperty → was: "Consider using Set-ADTRegistryKey"
These five entries are completely removed from the manualPatterns list. They will no longer trigger any warning in the PSADT Lifecycle compat check panel.
